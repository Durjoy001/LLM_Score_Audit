ThaBIT ?!?
ThaBIT got its name from Upsilon Orionis - a star in the constellation Orion.
It has the traditional name Thabit (Arabic for "the imperturbable one").
Since 1943, the spectrum of this star has served as one of the stable
anchor points by which other stars are classified.

ThaBIT is a versatile 3D environment written in C++ which primarily serves
as a user interface wrapper. ThaBIT allows you to interact with your
computer in a more natural way. Internet Browsing, File System Browsing,
and interaction with network devices is our primary goals for Alpha RC1.
Being written on C++ means that it is very fast. This allows us to run it on
ARM, Android and IOS systems without any problems. Those devices can
then be mount on your computer through a network and appear as a
separate 'worlds' where [ie] pictures are represented as 3D objects.
ThaBIT organizes the environment ( known as a 'space' ) in units ( named
'Worlds' ). The position of the worlds is highly configurable. As a matter of
fact, entire project is made to be very flexible.
Each World can be as big as you need it to be. It can represent multiple
local environments defined for specific purpose or it can represent
network devices. In a 'World', we then place 'Plugins'. 'Plugin' can be
easily created and we will provide full how-to documentation along with
our source code. Plugin can be whatever you want it to be ( Browser,
Picture viewer, Video Player, File manager....). Actually, whatever you can
make in C++. 3D Objects are any 3D Studio Max object ( or a group of
objects ), and support for many other objects is on the way. Of course,
OpenGl people will have the options to include their own projects.
We are also working hard on networking for this project - like file sharing
among network computers ( LAN/WAN ) and there's also an effort to
provide P2P networking. We are currently looking into a possibility of a
server implementation and natural moving through remote worlds ( avatar
interactions ) and visualization of network traffic.

We will provide many plugins but we can't provide plugins for all possible
applications. We are hoping to make environment in which users can easily
create plugins which suit their own needs and then share those plugins
with people they know. ThaBIT will not have any central authority or
mandatory repository or any such service. The environment will be yours
to customize it for your own needs. We will, however, publish our own
plugins for people who want to see what we are up to.
Why Kickstarter ?
This project is not monetary oriented. We are not making a 'service' or a
product. We strongly believe in Open source community. This is why we
have decided to make this project open. The least we are hoping to do is
inspire other people to start making similar software packets and push tech
industry a little further. Failure will probably mean that we will need to ask
for support in some other places and indefinitely delay the release of this
project. We would like to avoid that.

So why not github ?
We would prefer to finish base the framework before Alpha 1, polish in Beta
1 and then push it to github. We believe that announcing github repo this
early will dilute the project and delay the final solution. We also hope to
cover some of our expenses with kickstarter ( some programmers,
equipment and utility )
What Is the status of this project ?
ThaBIT is currently 60% done. 80% of backend is finished and only 40%
of front end. We are hoping to finish ( with your help ) this stage of the
project by the late April and push Alpha version to our friends and
contributors. After that, we will move to cosmetic work ( ie photo realistic
3D objects ) and bugs. With Alpha release published we will finish then
basic plugins ( 60% is already done ). After that comes polishing, bugs,
suggestions and corrections and beta could be expected by the end of the
summer ( possibly mid summer ).

Risks and challenges
Considering that this is not a product or a service, we do not face the same
risks and challenges as other projects. The work on this framework is
continuous and ongoing. We cannot lose financing or sponsors or face any
similar challenge. The only obstacle that we can see ( or imagine
happening ) is a lack of time. This would only delay the project release
date but the project itself would survive. This is the main reason for
kickstarter project. After this campaign is over ( and hopefully successful )
our team members will be able to dedicate their full time for finishing this
project. (example: we can get photorealistic 3D models from 3D artists
instead of spending 2 months making them - so we can dedicate our time
to programming )
